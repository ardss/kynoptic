# KY(Kynoptic)维护约定

> 面向仓库协作者的工程约定:主线、分支、发布与临时工作区规则。
> 部署环境、设备与本地运维细节保存在各协作者本地维护档案,不入库。

## 1. 唯一事实源

- 唯一开发仓库即本仓库(`github.com/ardss/kynoptic`);`main` 始终跟踪上游,本地仅允许 docs-only 提交(同步用 `git pull --rebase`)。
- 版本基线以 tag 与 CHANGELOG 为准;运行实例核验:`/api/status` 的 `build.git_hash` 应等于对应 tag 的提交。
- 判断"最新版本"永远以 Git HEAD + tag 为准,不认文件夹名或文件修改时间。
- 功能开发一律从本仓库派生分支;禁止再建立第二套主仓库或独立历史线。

## 2. 路径边界

- 开发源码、正式安装目录、生产数据库、日志四类路径互不混用;不把数据库、安装包或大体积备份放进源码仓库。
- 重装/升级使用独立分支构建的安装包,先在隔离数据目录与独立端口上验证;不因源码整理而停用正式程序。

## 3. 版本、构建与验收流程

1. 开发:`cargo build` / `cargo test`(全 workspace)。
2. 候选版本:独立分支构建安装包(`kynoptic.iss`),隔离数据目录 + 独立端口验证。
3. 验收:构建机隔离验证 → 验收机安装验收 → 明确的用户 GO 才允许 tag/Release。
4. 发布:tag 默认 draft,公开发布需明确批准。
5. 升级安装后核对 `/api/status` 的 `build.git_hash` 与迁移编号(当前官方迁移链 0014-0020)。

## 4. 临时工作区(worktree)生命周期

1. 并行开发用 `git worktree add` 创建临时目录,命名 `KY-<topic>-<date>`,并登记用途、分支、创建日期与退出条件。
2. 完成后合并或明确放弃 → `git worktree remove` → 记录收尾;禁止把发布候选工作区当永久主目录。
3. 清理任何 worktree 前确认其 Git 主仓库不因此失效。

## 5. 历史孤立线与迁移链警告

- 项目历史上曾存在两条与上游无共同提交历史的孤立线(0.7 体系、0.8.2-rc 体系);与主线对照一律采用内容级比对,不用提交号祖先关系。
- 孤立线的 SQLite 迁移(0015-0017)与官方迁移链**同名不同物**,官方 0020 迁移已自愈其残留——**禁止移植**;移植任何旧功能前先核对迁移链。
