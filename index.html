How it works

Three steps. Any AI.

Install, let it listen, and give your AI a grounded view of what your machine has been doing.

01

Sense

Lightweight native monitors capture event-level activity — window switches, input counts, CPU/GPU/thermal, network, devices. Activity type, never content.

02

Store

Everything lands in one local SQLite file with an open, documented schema. KB-scale per day. Yours to open, query, or delete.

03

Serve to any AI

A built-in MCP server plus CLI expose your machine's history to Claude Desktop, Cursor, or any MCP client — model-agnostic.

Claude Desktop / Cursor — MCP config
// one file, any MCP client
{
  "mcpServers": {
    "Kynoptic": {
      "command": "Kynoptic-mcp",
      "args": ["serve"]
    }
  }
}

# or straight from the CLI
$ Kynoptic query --from yesterday --metric thermal --join window
Features

Near-zero cost, smallest possible privacy surface, and data an AI can actually compute with.

📡

Win32-native coverage across activity, hardware, network, peripherals, audio, and environment. Zero Python runtime.

Privacy

The whole policy, in three sentences

Full details live in PRIVACY.md — plain language, monitor by monitor.

No keylogging

Kynoptic does not record, store, or transmit the content of your keystrokes. Only aggregate counts of key/mouse events are stored locally — and password fields are excluded entirely, not even a count.

No screen pixels

No screenshots, no frames, no OCR. There is nothing to replay and nothing to leak — the smallest possible privacy surface by construction.

Local only

All data lives in a single SQLite file on your device. Nothing is uploaded; we, the developers, have no access. Verify by auditing the open source — there is no outbound connection.

FAQ

Common questions

Where does my data go?

Nowhere. It stays in a local SQLite file on your machine. There are no servers, no telemetry, and no upload code path — you can verify this by observing that the process makes no outbound connections.

Does it record my screen or my passwords?

No screens — and password fields are auto-filtered at the hook level: typing in a password box produces no data at all, not even a count. With --no-text, even window titles are not stored.

How many resources does it use?

Event-level capture is designed to be near-zero: no video encoding, no OCR, no cloud calls. Writes are batched (300 events / 5 s flush) to minimize disk I/O.

How is this different from Windows Recall or Rewind?

Those rebuild your screen — a replayable record of everything you saw. Kynoptic never captures pixels; it stores structured events (which app, how active, what the hardware was doing). Think "fitness tracker for your computer," not "black box for your screen."

Which AI assistants can connect to it?

Any MCP-capable client — Claude Desktop, Cursor, and other MCP hosts — via the built-in MCP server. Not using MCP? Query the same data via CLI or plain SQL against the open schema. Model-agnostic.

Why Windows first, and what's the license?

Windows is where the demand and testing surface are, and it lets us build native monitors on plain Win32 APIs — macOS and Linux are on the roadmap. License: MIT, fully open source and auditable.
